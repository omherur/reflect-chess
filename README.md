# ReflectChess

Chess engines tell you which move was wrong. ReflectChess captures what you were actually
thinking *before* the engine reveals the verdict — so later versions can find the thinking
mistakes you keep making, not just the tactical ones.

This is the MVP: it builds the core capture loop only. Cross-game pattern-mining comes in a
later phase, once real reflection data exists.

## How it works

For each imported game, ReflectChess:

1. Analyzes the game with a local Stockfish engine (quick scan of every position, then a
   deeper multi-line scan of the moments that matter).
2. Picks 5–9 key moments — positions with a significant evaluation swing, a missed tactic, or
   the start of a forced sequence — and groups consecutive moves that are all downstream of
   the same original mistake into a single moment. Every game gets at least 5 key moments
   (down to genuinely tiny swings, or well-played moments worth reinforcing positively) so a
   clean game never feels like a wasted analysis — see [Key-moment detection](#key-moment-detection-and-importance-ranking) below.
3. Shows you the board and the move you actually played at each key moment. That's historical
   fact, always visible. You can also freely browse every other move in the game — just no
   reflection prompt outside a flagged key moment.
4. **Hides the engine's evaluation, verdict, best move, and importance ranking.**
5. Asks what you were thinking when you played the move, in your own words.
6. Asks what you'd play now, if you could replay the position — on the board, by typing a
   move, or by saying you'd play the same move again.
7. Only after both answers are submitted does it reveal the engine's evaluation, the best
   move, how your replay move compares, and a personalized, plain-English explanation —
   generated by Claude — of why your original move worked or failed.

The engine's opinion is never shown before both questions are answered — that's the one rule
the whole app is built around.

## Stack

- Next.js 16 (App Router) + TypeScript + React 19
- Tailwind CSS + shadcn/ui
- SQLite + Prisma
- `chess.js` for move validation/PGN parsing, `react-chessboard` for the board
- Stockfish 18 (WASM) running in a local child process, driven over UCI
- Claude (Haiku by default) for personalized explanations, behind a swappable interface with a
  deterministic template fallback

## Setup

Requires Node.js 20.9+ (Next.js 16's minimum).

```bash
npm install
npx prisma migrate dev
npm run seed
npm run dev
```

Then open [http://localhost:3000](http://localhost:3000).

`npm run seed` imports two bundled sample games (a tactical blunder and a strategic mistake,
see below) and runs full Stockfish analysis on them, so the app is demonstrable without ever
touching Chess.com. It can take a minute or two — it's running a real engine.

### Enabling Claude explanations

Copy `.env.example` to `.env` and set `ANTHROPIC_API_KEY` to a real key to get warm,
personalized, Claude-generated explanations (model: `claude-haiku-4-5-20251001`). This is
**optional** — with no key set, or if the API call fails or times out, explanations fall back
automatically to the deterministic template provider, so the app works either way.

```bash
# .env
ANTHROPIC_API_KEY=sk-ant-...
```

### Starting over with a clean database

```bash
rm -f prisma/dev.db
npx prisma migrate deploy
npm run seed
```

Or use the "Clear all games" button on the dashboard to wipe imported games (and their moves,
key moments, and reflections) without touching the seeded local user.

### Running tests

```bash
npm run test
```

Tests spin up a throwaway SQLite database at `prisma/test.db` (via a Vitest global setup) and
clean it up afterward. Coverage includes PGN parsing, FEN generation for both colors,
duplicate-import prevention, evaluation/mate-score handling, key-moment selection (grouping,
the minimum-moment guarantee, and importance ranking), legal replay-move validation, concept
detection, and the explanation providers (including the Claude-provider prompt/response
parsing and the fallback behavior, both without needing a live API key).

### Design notes

- **The reveal gate lives in one place.** `src/server/keymoments.ts`'s `toClientView` is the
  only function allowed to serialize a `KeyMoment` for the client. It returns a narrow
  `KeyMomentPublic` type (just the position and the move played) until a `Reflection` exists,
  and only then returns the full `KeyMomentVerdict` — classification, importance tier,
  concepts, and explanation included. Every API route and page goes through it, so there's no
  code path that can leak engine output early. Even the key-moments sidebar's *sort order*
  (importance-first) is computed server-side from data the client never receives for
  unreflected moments — only the resulting order is visible, the same way "this move was
  flagged as a key moment" was already visible before any of this.
- **Explanations are generated at reflection time, not analysis time.** They're personalized
  to the player's own stated reasoning and replay move, so they literally can't exist before
  both reflection questions are answered — the timing itself enforces the gate. See
  `src/app/api/games/[id]/keymoments/[momentId]/reflect/route.ts`.
- **Explanations are behind an interface.** `src/server/explain/types.ts` defines
  `ExplanationProvider` with one method, `explainMove`. `ClaudeExplanationProvider` is the
  default (warm, specific, personalized — see its system prompt in `claude-provider.ts`);
  `TemplateExplanationProvider` is deterministic and used as both a direct option and the
  automatic fallback via `FallbackExplanationProvider`. Swapping in a different model or
  provider means writing one new class.
- **Concept detection** (`src/server/explain/concepts.ts`) looks for hanging pieces, forks,
  pins, back-rank weakness, and king exposure via static board inspection, and returns the
  actual squares involved so the board can highlight them at reveal time.
- **Platform adapters are isolated.** `src/lib/import/types.ts` defines a `PlatformAdapter`
  interface; `chesscom.ts` is the only implementation. Adding Lichess later means writing one
  new adapter and registering it — no changes to import UI, dedupe, or storage logic.
- **Analysis is a quick scan + a deep scan, both cached.** Every position in a game gets a fast
  depth-10, single-line scan (cached by FEN + settings in `AnalysisCache`). Only the positions
  selected as key moments get a deeper depth-16, multi-line scan — that's also where the best
  move, principal variation, classification, and importance ranking come from.

### Key-moment detection and importance ranking

Detection runs in increasingly lenient passes so every game yields at least 5 key moments
(capped at 9), never just the one or two biggest blunders:

1. **Strict pass**: moves with a large evaluation swing (≥0.9 pawns), a missed forced mate, or
   similar — the "obvious" mistakes.
2. **Lower-bar pass**: if still short, moves with a smaller-but-real swing (≥0.4 pawns).
3. **Positive-reinforcement pass**: if *still* short, moves that significantly *improved* the
   position — punishing an opponent's error, finding a strong idea in a sharp position — so a
   genuinely well-played game surfaces difficult moments handled well, not just mistakes.
4. **No-floor pass**: for very short games, whatever's left, ranked by magnitude, so the
   guarantee holds whenever enough distinct moves exist to fill it.

Passes 1 and the initial grouping step also collapse multiple flagged moves that are all
downstream of the same original mistake into a single moment (e.g. a hung queen followed by
the forced recapture doesn't produce two key moments).

Each key moment then gets an importance score (0–100) from eval-swing magnitude, whether a
forced mate was missed or allowed, and tactical complexity (how close the engine's best and
second-best lines are), bucketed into **Critical** / **Notable** / **Minor**. The key-moments
sidebar sorts Critical first by default and gives them stronger visual treatment — but only
*after* a moment is reflected on; before that, only the move itself and review status are
shown, per the reveal gate above.

## Known limitations

This is a deliberately narrow MVP. Explicitly **not** built yet:

- **Lichess import.** Only Chess.com (public Published-Data API) and manual PGN paste are
  supported. The platform-adapter interface is there so Lichess can be added without touching
  core logic, but no adapter exists yet.
- **Voice input** for the reflection questions.
- **Cross-game pattern-mining or an insights dashboard.** This version captures reflections;
  it doesn't yet look across games to find recurring thinking mistakes. That's the whole point
  of the next phase, once there's real reflection data to mine.
- **Payments** of any kind.
- **A shareable results card.**
- **Authentication.** There's a single seeded local user; this is a local-first app, not a
  multi-user product yet. "Clear all games" wipes that user's games, not the account itself.
- **Engine strength/depth are fixed** (depth 10 quick scan, depth 16 deep scan, using
  Stockfish's "lite-single" WASM build for fast local startup). There's no UI to change them.
- **Concept detection is heuristic**, not exhaustive — it looks for hanging pieces, forks,
  pins, back-rank weakness, and king exposure via static board inspection, not full engine
  tactical analysis. It's intentionally conservative about claiming a concept applies.
- **No streaming/loading skeleton for the Claude call** — the reveal is generated
  server-side as part of the reflect request, so submitting shows a brief "Revealing…" state
  rather than a token-by-token stream.
